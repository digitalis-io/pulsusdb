This is the artifact behind the per-shape cell counts quoted for the
ignored-number rules -- 504 cells for the exponent group, 216 for the f32
group. `compare.py` beside this file sends ONE body per case, so it pins one
cell per shape: one ignored position, one wire framing, one byte offset. The
claim those shapes carry is stronger than that -- that each shape's verdict
is a function of the REQUEST, not of where the token sits in the body or of
how the client chunked its writes -- so it needs an instrument that varies
the two things it says do not matter. `number_route_probe.py` is that
instrument, and the counts below are its output rather than a report of one.

    20 shapes x 3 ignored positions x 4 wire framings x 3 byte offsets
      exponent group  14 shapes x 36 = 504 cells
      f32 group        6 shapes x 36 = 216 cells
      controls         3 shapes      =  60 cells

Every cell's expected pair of statuses is written down in the script; a cell
whose observed pair differs comes back MOVED and the run exits 1.

WHY THE CONTROLS ARE LOAD-BEARING. The 20 shapes are claimed invariant across
framings and offsets. If the framing loop never reached upstream's decoder --
if the kernel coalesced the writes, or if the server buffered the whole body
before parsing -- all four framings would return the same status and the run
would be green anyway. A green run would then be evidence of nothing. So the
probe also sends a 400-digit run at the two offsets either side of upstream's
read-buffer boundary, where the verdict is known to depend on both knobs:

    400 nines at offset 111  204 upstream in one write and in 512-byte
                             chunks, 400 in 256- and 128-byte chunks
    400 nines at offset 112  400 upstream in all four framings

`trySkipNumber` walks the CURRENT READ BUFFER only (`for i := iter.head; i <
iter.tail`, iter_skip_strict.go:26 @ jsoniter v1.1.12) over the 512 bytes
`jsoniter.NewDecoder` hands it (config.go:366, reached from
unmarshal.DecodePushRequest, pkg/util/unmarshal/unmarshal.go:17 @ loki
v3.7.4), and reports "skipped" only on reaching a terminating byte inside
that window (:46-53) -- so offset + length + 1 = 512 is the last accepted
position in one write, and a 256-byte first read cuts the same token short.
Those two also re-derive round 18's 111/112 boundary on every run.

The third control is the registered divergence's headline row, and its claim
is the opposite one: 1,000 nines is 400 upstream in every cell, because 1,000
digits is longer than the whole window and cannot fit at any offset under any
framing, and no 1,000-digit value is representable in f64. That is why
`json/ignored-number-int-1000` is the row compare.py pins expect="DIFF" and
the fragile 400-nine one is not; here it is 36 cells rather than the 20 first
reported in round 17.

All three controls are the registered length divergence (ledger residual 10),
so PulsusDB answers 204 to all 60 of their cells. That is the divergence,
recorded cell by cell, not a surprise.

what run B demonstrates
-----------------------
Run B is the probe's own mutant, and it is what makes run A's green a
measurement rather than an assumption. Upstream's default one-week
`reject_old_samples` window refuses anything it would otherwise have STORED,
so re-sending the identical matrix with a fixed 2023 timestamp must turn
every accepted cell into a 400 -- 13 of the 20 shapes plus the accepted half
of ctl-400-nines-at-111, listed by name in run B's last paragraph. All 13
moved. The five exponent shapes and two f32 shapes upstream refuses at DECODE
never reach the timestamp check and did not move, which is the other half of
the demonstration: the mutant is selective, not a blanket 400.

PulsusDB has no reject_old_samples equivalent, so its column is identical in
both runs. That asymmetry is why the live matrix sends `now`: an earlier pass
of this probe used the fixed timestamp throughout and reported those shapes
MOVED, which is the observation this run turns into a repeatable check.

------------------------------------------------
1. THE CONTROLS BITE. `--delay 0` removes the pause between wire chunks, so
   the writes coalesce and the framing never reaches upstream's decoder. The
   20 shapes stayed green -- exactly the false green the controls exist to
   catch -- and the controls caught it:
