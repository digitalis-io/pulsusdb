#       v3.7.4 -- pkg/logql/log/pattern/ ':!*_test.go'
#
# WHAT THIS FILE IS. A **bounded inventory**, not a proof of
# completeness. Its scope is exactly: lines in NON-TEST files under
# pkg/logql/log/pattern/ at v3.7.4 that contain an error-creating call
# spelled `errors.New(`, `fmt.Errorf(` or `newParseError(`, or a sentinel
# return spelled `return Err[A-Z]`.
#
# WHAT IS OUTSIDE IT. An error created by a constructor under any other
# spelling. Nothing in this file or its tests can see such a line -- it is
# not classified, it is absent. The `newParseError(` term is in the regex
# because that is this package's constructor; it generalises to nothing.
#
# WHY IT STOPS HERE. Closing that gap needs a source-structural
# enumeration -- parsing Go and following error-typed values to their
# returns. Nothing in this repository parses Go and CI cannot, so the
# alternative is not a better instrument but another instrument with its
# own gap. Where nothing available closes it, say so and stop.
#
# WHAT STILL HOLDS DESPITE THE BOUND. Four of the five Producers below are
# tied to a live probe with a captured status and error text (the `Probe`
# rows of logql_pattern_expr_sites.tsv), so a rule we model is a rule the
# reference demonstrably has. What is unproven is the other direction --
# that it has no others.
#
# ONE STRUCTURAL BOUND, stated as falsifiable rather than as a
# measurement: pkg/logql/log/pattern/ imports only `fmt`, `sync`,
# `bytes`, `errors` and `unicode/utf8`, so no error can arrive from a
# Loki-internal callee and no stdlib callee in that set returns one. A
# re-pin that adds an import falsifies it. (The `| json` half's
# equivalent bound does NOT hold: `strconv.Atoi` is a stdlib callee that
# does return an error, and it is reachable -- see
# logql_json_expr_reference_error_sites.txt.)
