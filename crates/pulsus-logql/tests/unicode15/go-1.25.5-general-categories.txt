#
# WHY THIS IS COMMITTED (issue #392). PulsusDB's own tables come from
# regex-syntax 0.8.11, which carries Unicode 16.0.0. Nothing in the Rust
# toolchain can evaluate Unicode 15.0.0, so without this data the claim
# "the version skew is one-directional, so nothing the reference accepts
# is refused here" would be a remembered measurement with no failure
# mode. With it, identifier_charset.rs's
# the_unicode_version_skew_is_one_directional re-checks the claim on
# every run and fails the moment a code point that IS a letter (or a
# decimal digit) at the reference stops being one here.
#
# THIS IS NOT THE ACCEPT SURFACE and must never be used as one. The
# lexer's rule is Unicode 16.0.0 (src/unicode_ident_tables.rs), by the
# ruling on #392. This is the comparison baseline only.
#
# It is a .txt and not a .rs on purpose: a Rust char literal '\u{31350}'
# reads as the decimal literal 31350 to the reserved-live-test-port
# guard in crates/pulsus-server/tests/live_port_uniqueness.rs, which
# scans crates/*/tests/**/*.rs. Data belongs in a data file anyway.
#

# unicode.IsLetter / unicode.IsDigit and coalescing maximal runs:
#

#         if unicode.IsLetter(r) { /* coalesce into maximal ranges */ }
#     }
